- 更新时间：2026-05-27

---

## 2. 文档目标

本文件只定义 MVP 首版的学生端信息架构、核心页面和关键状态。

目标不是覆盖完整教育平台，而是指导以下主链路的页面设计与交互落地：

`首页 -> 上传题目 -> OCR 识别/修正 -> AI Tutor 对话 -> 结果页 -> 今日复习`

首版不包含家长端和管理端的详细 IA，它们仅保留在后续扩展中。

---

## 3. MVP 信息架构总览

```text
初中数学 AI Tutor
└── [S1] 学生端
    ├── [S1.1] 首页/做题入口
    ├── [S1.2] 上传题目页
    ├── [S1.3] OCR 识别结果与修正页
    ├── [S1.4] AI Tutor 对话页
    ├── [S1.5] 题目结果页
    ├── [S1.6] 今日复习页
    └── [S1.7] 学习记录/历史详情页
```

说明：

- `S1.3` 单独拆出，是因为“识别失败或低置信度后手动修题”是首版关键分支
- `S1.7` 用“学习记录/历史详情页”替代“直接回到历史对话页”，避免活跃会话和历史回放混淆

---

## 4. 角色与场景矩阵

| 角色 | 场景 | 入口页面 | 主要任务 |
|------|------|----------|----------|
| 学生 | 开始做题 | S1.1 首页 | 进入上传流程 |
| 学生 | 识别题目 | S1.2 上传题目 | 上传图片、等待识别 |
| 学生 | 校正题目 | S1.3 OCR 结果与修正 | 修正题干、确认开始 |
| 学生 | AI 陪做 | S1.4 AI Tutor 对话 | 输入想法、接收提示、继续作答 |
| 学生 | 查看结果 | S1.5 题目结果 | 查看本次收获、进入下一步 |
| 学生 | 完成复习 | S1.6 今日复习 | 查看并开始复习任务 |
| 学生 | 回看历史 | S1.7 学习记录/历史详情 | 查看历史记录与只读回放 |

## 5. 页面清单

### S1.1 首页/做题入口

**目的：** 用最少信息把学生带入主链路。

**核心元素：**

- 主 CTA：开始做题
- 今日复习入口
- 最近一次学习摘要

**依赖数据：**

- 今日待复习任务数
- 最近一次会话的完成状态

**页面结构：**

```text
┌─────────────────────────────────────┐
│  Logo                       [头像]  │
├─────────────────────────────────────┤
│                                     │
│      [ 开始做题 ]                   │
│                                     │
├─────────────────────────────────────┤
│  今日复习（3）                  →   │
├─────────────────────────────────────┤
│  最近一次学习                        │
│  一元二次方程｜提示2次完成          │
│  [ 查看记录 ]                       │
└─────────────────────────────────────┘
```

**状态：**

- 首次使用：强调“开始做第一道题”
- 有复习任务：展示任务数量
- 无复习任务：显示“今天暂无复习任务”

**设计约束：**

- 首版首页不展示复杂趋势图和多维画像
- 首版首页不承担分析功能

---

### S1.2 上传题目页

**目的：** 让学生最低门槛输入题目。

**核心元素：**

- 拍照上传
- 相册选择
- 上传说明

**依赖能力：**

- 图片上传
- OCR 识别请求

**页面结构：**

```text
┌─────────────────────────────────────┐
│  ← 返回                      [帮助] │
├─────────────────────────────────────┤
│                                     │
│      [ 拍照上传 ]                   │
│                                     │
│      [ 从相册选择 ]                 │
│                                     │
├─────────────────────────────────────┤
│  提示：                             │
│  - 尽量只拍一道题                   │
│  - 保持画面清晰                     │
│  - 支持截图上传                     │
└─────────────────────────────────────┘
```

**状态：**

- 空状态
- 上传中
- 识别中
- 上传失败

**异常说明：**

- 上传失败时直接原地重试，不跳页

---

### S1.3 OCR 识别结果与修正页

**目的：** 承接 OCR 成功、低置信度和失败后的修正流程。

**为什么必须单独成页：**

- 这是首版最关键的失败兜底页面
- 它直接决定学生能否顺利进入 Tutor 会话

**核心元素：**

- 识别后的题干文本
- 置信度提示
- 手动编辑入口
- 重新上传
- 开始做题

**依赖数据：**

- `normalizedText`
- `confidence`
- `needsManualConfirm`

**页面结构：**

```text
┌─────────────────────────────────────┐
│  ← 返回                      [帮助] │
├─────────────────────────────────────┤
│  识别结果                           │
│                                     │
│  ┌───────────────────────────────┐  │
│  │ 题目文本                       │  │
│  │ 可点击编辑                     │  │
│  └───────────────────────────────┘  │
│                                     │
│  识别置信度：85%                    │
│                                     │
│  [ 编辑题目 ]                       │
│  [ 重新上传 ]                       │
│                                     │
│  [ 开始做题 ]                       │
└─────────────────────────────────────┘
```

**状态：**

- 高置信度成功：默认展示“开始做题”
- 低置信度成功：高亮提示“请先确认题目内容”
- 识别失败：展示空白编辑区或重新上传

**关键交互规则：**

- 低置信度时，主按钮文案改为“确认题目并开始”
- OCR 失败时，仍允许学生手动输入题干后进入 Tutor

---

### S1.4 AI Tutor 对话页

**目的：** 承载“不会直接给答案，而是一步步陪做”的核心体验。

**核心元素：**

- 题目卡片
- 对话流
- 学生输入框
- 当前提示进度
- 次级操作：请求提示

**依赖数据：**

- 当前会话
- 最近消息
- 当前 `tutorState`
- 当前 `hintLevel`
- 最近一次评估结果

**页面结构：**

```text
┌─────────────────────────────────────┐
│  ← 返回      当前题目       [题目▼] │
├─────────────────────────────────────┤
│  [题目卡片：默认收起，可展开]       │
├─────────────────────────────────────┤
│  Tutor：这题更像方程、函数还是几何？│
│                                     │
│  学生：不会做                       │
│                                     │
│  Tutor：先别急。你先说题目让你求什么│
│                                     │
├─────────────────────────────────────┤
│  提示进度：第 2 层 / 共 5 层         │
├─────────────────────────────────────┤
│  [ 输入你的步骤或想法... ]           │
│                                     │
│  [ 发送 ]     [ 给我一点提示 ]       │
└─────────────────────────────────────┘
```

**状态：**

- 默认输入态
- Tutor 回复中
- 学生连续卡住
- 会话结束态

**关键交互规则：**

- 首版提示层级只展示 `共 5 层`
- `看详细解析` 不默认常驻
- 只有连续卡住达到阈值后，才露出“查看详细解析”
- “查看详细解析”属于终局动作，触发后会结束当前探索式引导

**按钮优先级：**

- 主操作：发送
- 次操作：给我一点提示
- 受控操作：查看详细解析

**不应出现：**

- 首轮就展示完整解法
- 对话页同时承载历史回放和实时会话

---

### S1.5 题目结果页

**目的：** 让学生知道这次练习的完成方式、关键问题和下一步动作。

**核心元素：**

- 完成状态
- 本次知识点
- 本次错因
- 下一步推荐

**依赖数据：**

- 会话完成状态
- 是否使用高层提示
- 错因记录
- 是否生成复习任务

**页面结构：**

```text
┌─────────────────────────────────────┐
│               已完成                │
├─────────────────────────────────────┤
│  本次完成方式：提示后完成           │
│                                     │
│  本次知识点：一元二次方程           │
│  本次错因：步骤跳跃                 │
│                                     │
│  系统建议：                         │
│  下次先把中间推导写完整             │
├─────────────────────────────────────┤
│  [ 继续做题 ]                       │
│  [ 查看今日复习 ]                   │
│  [ 返回首页 ]                       │
└─────────────────────────────────────┘
```

**状态：**

- 自主完成
- 提示后完成
- 查看解析后完成
- 有复习任务
- 无复习任务

**设计约束：**

- 结果页展示的是“学习反馈”，不是完整学习报告
- 首版不在结果页堆叠过多分析图表

---

### S1.6 今日复习页

**目的：** 把错误沉淀成可执行的复习动作。

**核心元素：**

- 今日待复习任务
- 任务来源
- 完成进度
- 开始复习

**依赖数据：**

- `review_tasks`

**页面结构：**

```text
┌─────────────────────────────────────┐
│  ← 返回        今日复习             │
├─────────────────────────────────────┤
│  今日共 3 个任务                    │
│  已完成 1 / 3                       │
├─────────────────────────────────────┤
│  任务 1                             │
│  知识点：一元二次方程               │
│  错因：步骤跳跃                     │
│  [ 开始复习 ]                       │
├─────────────────────────────────────┤
│  任务 2                             │
│  知识点：计算专题                   │
│  错因：计算错误                     │
│  [ 开始复习 ]                       │
└─────────────────────────────────────┘
```

**状态：**

- 无任务
- 有任务
- 全部完成

**首版简化规则：**

- 复习页先做列表，不强求复杂任务分组
- “变式题复习”和“错因专项”可先统一成复习任务卡片

---

### S1.7 学习记录/历史详情页

**目的：** 查看历史记录，并以只读方式回看过去的会话。

**为什么不直接跳回对话页：**

- 活跃会话和历史回放语义不同
- 历史详情应默认只读
- 避免误把旧会话当作继续中的 session

**核心元素：**

- 历史记录列表
- 完成状态
- 点击进入历史详情

**依赖数据：**

- 历史 session 列表
- 每个 session 的完成方式和错因摘要

**记录列表结构：**

```text
┌─────────────────────────────────────┐
│  ← 返回        学习记录             │
├─────────────────────────────────────┤
│  5月27日                            │
│  一元二次方程｜提示2次完成     →    │
│  三角形全等｜自主完成          →    │
├─────────────────────────────────────┤
│  5月26日                            │
│  一次函数｜查看解析完成        →    │
└─────────────────────────────────────┘
```

**历史详情结构：**

```text
┌─────────────────────────────────────┐
│  ← 返回       历史详情              │
├─────────────────────────────────────┤
│  题目：一元二次方程                 │
│  完成方式：提示2次完成              │
│  关键错因：步骤跳跃                 │
├─────────────────────────────────────┤
│  对话回放（只读）                   │
│  Tutor：...                         │
│  学生：...                          │
│  Tutor：...                         │
├─────────────────────────────────────┤
│  [ 再做一题 ]                       │
└─────────────────────────────────────┘
```

**状态：**

- 空状态
- 有历史记录
- 历史详情只读态

## 6. 页面跳转流程

```text
[S1.1 首页]
  -> [S1.2 上传题目]
      -> 上传成功/识别中
      -> [S1.3 OCR 识别结果与修正]
          -> 识别成功
              -> [S1.4 AI Tutor 对话页]
          -> 低置信度
              -> 手动修正题干
              -> [S1.4 AI Tutor 对话页]
          -> 识别失败
              -> 重新上传
              -> 或手动输入题干
              -> [S1.4 AI Tutor 对话页]

[S1.4 AI Tutor 对话页]
  -> 正常完成
      -> [S1.5 题目结果页]
  -> 查看详细解析后完成
      -> [S1.5 题目结果页]
  -> 放弃/超时
      -> [S1.1 首页]

[S1.5 题目结果页]
  -> 继续做题
      -> [S1.2 上传题目页]
  -> 查看今日复习
      -> [S1.6 今日复习页]
  -> 返回首页
      -> [S1.1 首页]

[S1.1 首页]
  -> 今日复习
      -> [S1.6 今日复习页]
  -> 查看记录
      -> [S1.7 学习记录/历史详情页]
```

## 7. 页面 MVP 优先级

| 页面 | 建议路由 | 优先级 | 说明 |
|------|----------|--------|------|
| S1.1 首页 | `/` | P0 | 必须有，主入口 |
| S1.2 上传题目 | `/upload` | P0 | 必须有，主输入 |
| S1.3 OCR 结果与修正 | `/problems/[id]/confirm` | P0 | 必须有，承接 OCR 失败和低置信度 |
| S1.4 AI Tutor 对话 | `/session/[id]` | P0 | 必须有，核心体验 |
| S1.5 题目结果 | `/result/[id]` | P0 | 必须有，完成反馈 |
| S1.6 今日复习 | `/review` | P1 | 学习闭环，建议首版保留简版 |
| S1.7 学习记录/历史详情 | `/history` | P2 | 可后置，但不要与实时对话混用 |

## 9. 后续扩展

以下内容不在本文件首版详细展开：

- 家长端学习概览
- 家长端薄弱点查看

## 10. 结论

这份 UX 文档的核心不是罗列更多页面，而是确保首版每一页都服务于同一条学习主链路：

`输入题目 -> 理解题目 -> 跟随 Tutor 一步步做 -> 获得反馈 -> 进入复习`

首版最重要的三个 UX 判断标准是：

1. 学生是否能快速进入做题，不被复杂首页分散注意力
2. OCR 出错时是否仍能顺利继续，不因识别失败流失
3. Tutor 对话页是否始终强化“陪做”而不是“直接给答案”
